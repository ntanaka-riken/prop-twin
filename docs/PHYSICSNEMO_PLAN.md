# PhysicsNeMo の評価計画:プロペラ装置を試験台に(2026-10-31 改訂)

**主目的は、NVIDIA PhysicsNeMo を実際の問題で評価することです。特に PINN を重視します。**
想定する使い方はメカトロニクス系のラピッドプロトタイピングで、最高の精度より「それなりの結果を早く出せるか」を問います。
プロペラ装置(130 モーター + 3 枚羽根 + 紙コップ + キッチンスケール)は、実測で答え合わせができる試験台として使います。
ツインを実測に合わせることは副目的になりました。

これまでの OpenFOAM の CFD(`cfd/`、`docs/CFD_PLAN.md` の段階 0〜3)は、**評価の正解データ**として固定します。
新しい CFD は、正解か学習データが足りないときだけ回します。

## 1. 評価の問い

設計者が形や回転数を変えたとき、**推力・空力トルク・天秤の読みが、どれだけ早く、どれだけ合って出てくるか**を比べます。

| 手法 | 1 問あたりの答えが出るまで | 期待する精度 | 準備の手間 |
|---|---|---|---|
| BEMT(平板の式、合わせ込み) | 1 秒未満 | 実測に合わせた範囲では合う。外挿は不明 | 実測が要る |
| BEMT + 翼断面 LES の表 | 1 秒未満 | 全速 +3〜13 %、低回転で大きく外れる(段階 1) | 表を作る CFD 約 400 ノード時間 |
| MRF(OpenFOAM、CPU) | メッシュ 3 分 + 計算 約 40 分 | 推力は合うが、天秤の読みは大きく外れる | メッシュの設定 |
| URANS(OpenFOAM、CPU) | 約 14 時間 | 天秤の読みが実測に近づく | 回転格子の設定 |
| **PINN**(PhysicsNeMo) | 1 条件ずつ学習、または条件を入力にした学習のあとは即答 | **これを測る** | 方程式・境界条件・形状の記述 |
| **データ駆動サロゲート**(Transolver、MeshGraphNet、DoMINO) | 学習のあとはミリ秒〜秒 | **これを測る** | 学習データ(CFD)が要る |

ラピッドプロトタイピングでは、**計算時間だけでなく、問いを立ててから答えが出るまでの経過時間**(設定、失敗、やり直しを含む)が効きます。両方を記録します。

## 2. PINN の評価(段階を踏んで難しくする)

PINN はデータなしで方程式だけから解けるので、学習データの CFD が要りません。うまくいけば、ラピッドプロトタイピングには最も魅力的な道具です。
一方で、低 Re のはく離、回転、複雑な形は苦手とされています。どこまで通用するかの境界を、易しい問題から順に測ります。

| # | 問題 | 正解 | 見るもの | 合格の目安 |
|---|---|---|---|---|
| C1 | 翼断面、Re 3000、迎角 4°(はく離なし)、定常 | 段階 1 の LES の平均 | cl・cd、圧力分布、学習時間 | cl ±10 %、cd ±20 % |
| C2 | 翼断面、迎角と Re を入力にした 1 つの PINN(パラメータ付き) | 段階 1 の LES(低迎角) | 極曲線を 1 回の学習で出せるか。380 ケースの LES との費用比 | C1 と同じ目安を迎角 0〜8° で |
| C3 | 軸対称の流れ場で、ロータを BEMT の体積力(アクチュエータディスク)で表し、コップ・はかりと一緒に解く | 段階 3 の URANS(天秤の読み、後流) | ロータとコップの干渉と天秤の読みを、羽根を解かずに出せるか | 天秤の読み ±0.3 gf、推力 ±10 % |
| C4 | C3 にコップとの距離・回転数を入力として加える | URANS / MRF 数本 | 設計の振り幅を即答できるか | C3 と同じ |
| C5 | 3 次元の回転する羽根(回転座標) | 段階 2・3 | 限界の確認。通らないことの記録も成果とする | — |
| C6 | データ同化つき PINN:C3 に CFD の点データ(少数)か実測を混ぜる | URANS | データを少し足すと、どこまで良くなるか | — |

- **C3 がラピッドプロトタイピングの本命です**。実務で知りたいのは「この配置で力がどう出るか」で、羽根の表面の細部ではないからです。BEMT と PINN を組み合わせ、BEMT が苦手な周りの物との干渉だけを PINN に解かせます。
- 各問題で、ネットワークの大きさ、点の数、損失の重み、学習時間を記録し、失敗した設定も残します。
- PINN は、PhysicsNeMo 26.05 で本体に統合された Sym の機能を使います。統合後の API はまだ確かめていません(§6)。

## 3. データ駆動サロゲートの評価

| # | 問題 | 学習データ | モデル | 基準 |
|---|---|---|---|---|
| A | 翼断面の係数と平均の流れ場 | 段階 1 の 380 ケース(そろっている) | MLP、Transolver、MeshGraphNet | 線形補間(`bemt.SectionPolar`)、ガウス過程 |
| B | 回るプロペラの力と表面圧(形と回転数を振る) | MRF 200〜300 ケース(CPU で新たに作る)+ URANS 5〜10 本 | Transolver、DoMINO、X-MeshGraphNet。安い MRF と高い URANS を組み合わせる多精度の学習 | POD + ガウス過程 |

- 学習データの費用も手法の費用に含めます(§4)。
- B の MRF は CPU だけで回るので、同じノードの GPU で学習を並行できます(`--exclusive` を外せるかは要確認)。

## 4. 計算量と経過時間の数え方

- **主な単位は理究の GB200 ノード時間**です。CFD は CPU だけを使い、GPU 4 枚は遊んでいるので、ノード単位で数えます。PhysicsNeMo は GPU 4 枚 = 1 ノードとします。
- **費用の内訳**:学習データの CFD 費用、学習の費用、1 問あたりの予測の費用。PINN は学習データの費用が 0 で、学習が「解く」ことに当たります。
- **損益分岐の回数**:N* = (データの費用 + 学習の費用) / (CFD 1 ケースの費用 − 予測 1 回の費用)。
- **経過時間**:問いを決めてから使える答えが出るまで。設定にかかった時間と失敗した試行も含めます。
- CFD の費用は `cfd/bench/cfd_cost.py` で集めます(ケースごとのセル数・並列数・経過時間・コア時間・ノード時間、`--sacct` で Slurm のジョブ一覧。課題番号やユーザー ID は出力しません)。

```bash
ssh rikyu 'bash -lc "python3 \$W/cfd/bench/cfd_cost.py \$W/runs --sacct"' > twin/data/cfd/cost.json
```

CFD 側の実績(2026-10-31 朝、`twin/data/cfd/cost.json`):

| 計算 | セル数 | 1 ケースの費用 | 経過時間 |
|---|---|---|---|
| 翼断面 LES、Re 6000〜20000(16 c/U) | 61〜65 万 | 約 0.83 ノード時間(36 コア) | 約 3.3 時間 |
| 翼断面 LES、Re 3000 | 同上 | 約 3.7 ノード時間 | 約 15 時間 |
| MRF RANS L0 / L1(4000 反復) | 426 万 / 2239 万 | 0.6〜0.7 / 約 4.4 ノード時間 | 40 分 / 4.4 時間 |
| URANS L0(15 回転) | 471 万 | 約 27 ノード時間(2 ノード) | 約 14 時間 |

翼断面 380 ケースの合計は約 400 ノード時間です。課題 A の「データの費用」になります。

## 5. 精度の測り方

- **学習に入れていないケースで測ります**。抜き方は課題ごとに固定し、どの手法にも同じものを使います。
  - A:迎角を 1 つおきに抜く、Re 6000 を丸ごと抜く、Re 3000 への外挿。
  - B:回転数を 1 つ抜く、形の振り幅の端を抜く。
- **正解自身の不確かさを下限にします**。段階 1 は平均の揺れ(`reduce_sections.py` の `_std`・`_drift`)、3 次元は格子 L0 と L1 の差(推力で約 1 割)です。
- **実測とも比べます**。推力 5 点と逆転の天秤の読みです。正解の CFD 自体が実測からずれている(正転の天秤の読みは実測の半分弱)ので、「CFD に対する誤差」と「実測に対する誤差」を分けて書きます。
- **学習曲線**:データ駆動の手法は、学習データを 25・50・100 % に減らして測ります。PINN は、点の数と学習時間を増やしたときの誤差を測ります。計算量と精度の関係を示す主な図です。

## 9. 結果(1 日目、2026-10-31)

記録は `twin/data/cfd/ml_bench.json`、図は `twin/data/cfd/pinn_c1.png`(学習の経過)と `pinn_c1_fields.png`(流れ場)です。

### 課題 A の基準(`cfd/bench/task_a_baselines.py`)

| 手法 | 迎角 1 つおき | Re 10000 を抜く | Re 3000 へ外挿 |
|---|---|---|---|
| 線形補間(0.02 秒) | cl 0.090 / cd 0.025 | cl 0.088 / cd 0.026 | cl 0.119 / cd 0.041 |
| ガウス過程(6〜13 秒) | cl 0.077 / cd 0.022 | cl 0.089 / cd 0.028 | cl 0.123 / cd 0.042 |
| (参考)LES 自身の平均の揺れ | cl 0.054 / cd 0.010 | cl 0.085 / cd 0.013 | cl 0.077 / cd 0.014 |

数値は平均絶対誤差です。迎角 8° 以下に限ると、どちらも cl 0.02〜0.05 です。誤差の大半は、はく離した高迎角で LES 自身の平均が揺れていることによります。学習モデルがこれを大きく下回るのは難しく、課題 A は「基準と同等か」を問う形になります。

### PINN C1(翼断面 1 条件、Re 6000・迎角 4°・t/c 0.03・f/c 0.03)

| 手法 | 計算資源 | 時間 | cl | cd |
|---|---|---|---|---|
| LES(正解、段階 1) | CPU 36 コア | 3.3 時間 | 0.552 | 0.055 |
| **OpenFOAM 2 次元定常**(simpleFoam 層流、3.8 万セル) | CPU 4 コア | **6.7 秒** | 0.531(−4 %) | 0.053(−4 %) |
| PINN 教科書どおり(u・v・p、壁は罰則項、2 万ステップ) | GPU 1 枚 | 29 分 | 0.000 | 0.000 |
| 同、4 万ステップ | GPU 1 枚 | 57 分 | 0.000 | −0.001 |
| 同、壁の重み 100 | GPU 1 枚 | 29 分 | 0.000 | 0.000 |
| PINN 流れ関数 + 壁を式で厳密化 + L-BFGS(δ 0.1 / 0.03) | GPU 1 枚 | 65 分 | 0.000 | 0.001 / 0.000 |

検算の Re 200 でも、PINN は 4 本とも cl・cd がほぼ 0 でした(OpenFOAM の 2 次元定常は、同じ設定では Re 200 で収束せず。Re 200 の LES は、8 時間で 16 c/U のうち 0.54 しか進まず、約 230 時間かかる見込みのため打ち切り)。

- **失敗の仕方**:どの PINN も、翼の上下 0.1 c ほどを止まった流体の塊で包みます。壁での速度の傾きはほぼ 0 で、その外側では圧力がほぼ一様です。そのため揚力も抗力も出ません。教科書どおりの形では、全体の質量保存も 7〜13 % 破れていました(流れ関数の形では 1〜2 %)。
- **損失は小さい**:方程式の残差の平均は 1e-3〜1e-4 まで下がります。「損失が下がった」ことは、答えが正しいことを意味しません。正解なしで PINN だけを使う実務では、ここが一番の落とし穴です。
- **1 条件を解く速さ**:OpenFOAM の 2 次元定常は 7 秒で LES と 4 % 以内に合いました。PINN は 30〜65 分かけても答えになっていません。1 条件を解く用途では、PINN は比較になりません。
- **PhysicsNeMo の部品**:方程式の記述と残差の計算(`PDE`、`PhysicsInformer`)は問題なく使えました。点の配置、境界条件、距離関数、力の積分はすべて自前で書いています。

### PINN C6(C1 と同じ断面に、LES の時間平均の点データを混ぜる)

データは LES(re06000_t030_f030_a+04)の時間平均を、ランダムな点(半分は翼から 0.3 c 以内)で取り出し、スパン方向に平均したものです(`cfd/pinn/les_samples.py`、`cfd/rikyu/10_les_sample.sbatch`)。
評価は、学習に使っていない 4,945 点です。比べる相手は、同じネットワークを方程式なしでデータだけに当てはめたもの(`--no-pde`)です。図は `twin/data/cfd/pinn_c6.png` です。

| 点の数 | PINN + データ(14 分):cl / cd / u・p の誤差 | データだけ(24 秒):cl / cd / u・p の誤差 |
|---|---|---|
| 30 | 0.085 / 0.027 / 12 %・92 % | 0.104 / 0.029 / 45 %・95 % |
| 100 | 0.418 / 0.045 / **7 %・42 %** | 0.341 / 0.066 / 14 %・102 % |
| 300 | 0.373 / 0.044 / 7 %・48 % | 0.415 / 0.044 / 3 %・28 % |
| 1,000 | 0.424 / 0.045 / 6 %・41 % | **0.481 / 0.054 / 3 %・17 %** |
| 10,000 | 0.394 / 0.043 / 6 %・45 % | 0.495 / 0.044 / 1 %・8 % |
| (正解 LES) | 0.552 / 0.055 | |

- **データがごく少ない(100 点程度)ときだけ、方程式が効きます**。流れ場の誤差は、データだけの半分以下(u 7 % 対 14 %、p 42 % 対 102 %)です。C1 で出なかった揚力も、100 点で cl 0.42 まで出ました。
- **300 点を超えると、データだけのほうが良くなります**。PINN はデータを増やしても cl −25 %・cd −20 %・p 40 % 前後で頭打ちです。方程式の項がデータと食い違う向きに引っ張っています。考えられる原因は 2 つです。
  - 定常・層流の方程式と、LES の時間平均(乱れの寄与を含む)のずれ
  - C1 で見た「止まった流体の塊」に向かう最適化の癖
- **時間**:PINN は 1 本 14 分、データだけは 24 秒です(どちらも GPU 1 枚)。
- **実務への含意**:流れ場の計測や CFD の点が数十〜百点しかないとき(たとえば PIV の一部や圧力孔)は、PINN で補間・補完する価値があります。数百点以上あるなら、まずデータだけの当てはめ(ニューラルネットやガウス過程)を試すべきです。
- **未調整の設定**:データの重み(10)、ネットワークの大きさ、ステップ数は振っていません。PINN の頭打ちは、重みの調整で多少動く可能性があります。

### PINN C2(迎角を入力にした 1 つのネットワーク、Re 6000・t/c 0.03・f/c 0.03、迎角 −4〜10°)

方程式は −5〜11° の連続な迎角で課し、LES の点データは −4・0・4・8° だけに与えました(`cfd/pinn/c2_param.py`)。評価は −2・2・6°(内挿)と 10°(外挿)で行いました。
基準として、OpenFOAM の 2 次元層流を全迎角で解いています。定常(simpleFoam)と非定常(pimpleFoam、16 c/U、`make_section.py --transient2d`)の 2 通りです。図は `twin/data/cfd/pinn_c2.png` です。

| cl(LES との比) | −2° | 2° | 6° | 10°(外挿) | 時間 |
|---|---|---|---|---|---|
| LES(正解) | −0.054 | 0.371 | 0.926 | 1.151 | 1 迎角 3.3 時間(36 コア) |
| OpenFOAM 2D 定常 | 収束せず | 0.374 | 収束せず | 収束せず | 収束時 7 秒(4 コア) |
| OpenFOAM 2D 非定常 | −0.231 | 0.386 | 0.978 | 1.175 | 1 迎角 8〜13 分(4 コア) |
| PINN、データなし | 0 | 0 | 0 | 0 | 29 分(GPU 1 枚) |
| PINN + 4 迎角 × 1,000 点 | −0.034 | 0.344 | **0.434** | **0.318** | 29 分 |
| データだけ、4 迎角 × 1,000 点 | −0.132 | 0.356 | 0.576 | 0.567 | 1 分 |

- **データなしの PINN は、迎角を入力にしても全迎角で揚力 0 でした**(C1 と同じ失敗)。
- **データ付きの学習モデルは、はく離のない範囲(−4〜4°)の内挿ならおおむね使えます**(2° で cl −4〜7 %)。ただし、はく離が始まる 6° と外挿の 10° では、LES の半分程度の揚力しか出ません。データのない迎角の非線形な変化(失速の始まり)は、方程式を入れても学べませんでした。
- **PINN + データとデータだけの差は小さいです**。データのない迎角での流れ場の u の誤差は、PINN 5〜12 %、データだけ 5〜14 % です。時間は PINN が 29 倍かかります。
- **OpenFOAM 2D 非定常**:はく離のない範囲で LES とほぼ一致しました(4°:cl 0.553 対 0.552、cd 0.0549 対 0.0548)。はく離した 8° では揚力を 26 % 大きく出しました。2 次元では、はく離した流れが 3 次元的に崩れる効果を表せないためです。全 8 迎角で 1.5 時間(4 コア × 8 本を並列にすれば 13 分)です。
- **ラピッドプロトタイピングとしての結論**:極曲線(迎角ごとの cl・cd)を早く得たいなら、OpenFOAM の 2 次元計算(はく離のない範囲は定常で 7 秒、それ以外は非定常で 10 分)が、PINN より速く確かです。学習モデルが勝てるのは、何百回も問い合わせる場合と、データのある範囲の内挿だけです。

### GPU の CFD:格子ボルツマン法(XLB、C2 と同じ断面、2026-11-01)

PINN と同じ GPU 1 枚(GB200)で、古典的な CFD がどこまで速く確かかを測りました。XLB 0.3.1(Autodesk、Apache 2.0)の Warp 版で、断面を 2 次元の格子ボルツマン法で解いています(`cfd/xlb/section_lbm.py`、ジョブは `cfd/rikyu/12_xlb.sbatch`)。
- **計算の条件**:D2Q9、KBC 衝突、等間隔格子、領域は翼弦の −3〜7 c × ±4 c、壁は階段状のはね返し、力は運動量交換法です。OpenFOAM と同じく、16 c/U まで解いて t = 6〜16 で平均しました。
- **導入**:XLB と jax は PhysicsNeMo のイメージに入っていません。`$W/pylib/site` に `pip --target` で入れました。XLB 0.3.1 が使う関数(`wp.mat`)はイメージの Warp 1.16 で消えているので、Warp 1.11.1 を別のディレクトリに入れて先に読み込みます。
- **XLB の不具合**:XLB の力の計算は 2 次元で動かないので(3 次元の速度成分を読みにいくため)、直した版をスクリプトに持っています。
- **速さ**:GPU 1 枚で毎秒 84〜164 億セル更新でした。
- **結果**:LES との比較と図は `cfd/xlb/compare_xlb.py`、`twin/data/cfd/xlb_c2.png`、`ml_bench.json`(課題 `CFD-GPU`)です。

| cl | −4° | −2° | 0° | 2° | 4° | 6° | 8° | 10° | 1 迎角の時間 |
|---|---|---|---|---|---|---|---|---|---|
| LES(正解) | −0.418 | −0.054 | 0.185 | 0.371 | 0.552 | 0.926 | 0.913 | 1.151 | 3.3 時間(36 コア) |
| OpenFOAM 2D 非定常 | −0.438 | −0.231 | 0.190 | 0.386 | 0.553 | 0.978 | 1.154 | 1.175 | 8〜13 分(4 コア) |
| XLB 2D、256 セル/c(524 万セル) | −0.347 | −0.242 | 0.180 | 0.406 | 0.606 | 0.957 | 1.233 | 1.375 | **34 秒**(GPU 1 枚) |
| XLB 2D、512 セル/c(2,097 万セル) | −0.374 | −0.214 | 0.198 | 0.393 | 0.589 | 0.977 | 1.181 | 1.379 | 3.5 分(GPU 1 枚) |
| XLB 3D、128 セル/c、幅 0.2 c 周期(3,408 万セル) | | | | | 0.609 | | **0.925** | | 4.1 分(GPU 1 枚) |
| PINN + 4 迎角 × 1,000 点(C2) | | −0.034 | | 0.344 | | 0.434 | | 0.318 | 29 分(GPU 1 枚) |

- **精度は OpenFOAM 2D とほぼ同じです**。はく離のない範囲(0〜6°)で、LES との差は cl で +2〜10 %、cd で +1〜10 % です。8°・10° で揚力を大きく出すのと、−2° のずれは OpenFOAM 2D と同じで、2 次元計算そのものの限界です(はく離した流れの 3 次元的な崩れを表せない)。
- **格子の細かさ**:4° で、1 翼弦 128・256・512 セルの cl は 0.577・0.606・0.589、cd は 0.0638・0.0607・0.0573 でした。cd は細かくするほど LES(0.0548)に近づきます。cl の差 7 % は、階段状の壁の近似が主な原因と考えられます。
- **領域の大きさ**:外側の境界を ±4 c から ±8 c に広げても、cl は 1 % しか変わりませんでした(0.606 → 0.599)。
- **計算量(1 迎角)**:
  - XLB 256 セル/c は 0.0024 ノード時間です(GPU 1 枚 = 1/4 ノード)。
  - OpenFOAM 2D 非定常は 0.005 ノード時間です(4/144 ノード × 10 分)。
  - 答えまでの時間は、XLB が OpenFOAM の約 1/15〜1/20、PINN の約 1/50 です。
  - 8 迎角の極曲線なら、XLB は GPU 1 枚で約 5 分です。GPU 4 枚に分ければ約 1 分です。
- **結論**:「GPU 1 枚で、それなりの答えを早く」という問いには、PINN より GPU の CFD(格子ボルツマン法)のほうがはるかに良い答えです。同じ GPU で PINN の 50 倍速く、データなしで、OpenFOAM と同等の精度が出ます。PINN が意味を持つのは、データとの融合(C6 のような疎な計測の補完)に限られます。
- **限界**:
  - 壁は階段状で、薄い翼(t/c 0.03)の厚さは 256 セル/c で 8 セルしかありません。
  - 壁の近くだけ格子を細かくする機能は、XLB では GPU 1 枚の Neon 版にしかありません。
  - 回転する羽根(段階 3 の URANS)は、XLB の公開版では扱えない見込みです。

- **3 次元(2026-11-01 追加)**:LES と同じく幅 0.2 c を周期にした D3Q27 で、4° と 8° だけ解きました(`section_lbm.py --span 0.2`)。
  - 8° の cl は 0.925 で、LES(0.913)との差は 1 % です。2 次元の 1.18〜1.23 の過大が消えました。cd は LES との差 0.016 です。
  - 4° の cl は 0.609(LES 0.552、+10 %)で、2 次元 128 セル/c(0.577)と同程度です。差は主に階段状の壁から来ています。
  - 1 迎角 245 秒(毎秒 570 億セル更新、0.017 ノード時間)です。はく離する迎角の誤差を、OpenFOAM 2D と同じくらいの時間で直せます。
  - **XLB 0.3.1 の 3 次元の境界条件**:流入の RegularizedBC と流出の ExtrapolationOutflowBC は、3 次元では空の風洞でも発散しました(流入で最初から密度の誤差 0.07)。3 次元では流入・流出・外側をすべて平衡分布の境界(EquilibriumBC)にしています。また、XLB の bottom/top は 3 次元では z の面なので、面の番号は自分で作っています。

### OpenFOAM を丸ごと GPU で動かす SPUMA(調べただけ、2026-11-01)

- **何か**:CINECA が作っている OpenFOAM の GPU 版です(GPL3、[GitLab](https://gitlab.hpc.cineca.it/exafoam/spuma))。最新版 0.3-v2512 は、理究の OpenFOAM と同じ v2512 がもとです。
- **GPU 対応の機能**:
  - ソルバ:simpleFoam、pimpleFoam、SRFSimpleFoam など
  - 乱流モデル:k-ω SST、DES・DDES、LES(Smagorinsky、WALE、kEqn)
  - GAMG などの線形ソルバ
  - AMI の補間
- **未対応・未確認の機能**:
  - 回転機械用の「格子どうしのつなぎ目」は開発中です(2026 年 10 月の発表資料)。段階 3 の回転格子 URANS がそのまま速くなるかは未確認です。
  - MRF は対応一覧に載っていません。未対応の機能は CPU で動き、そのぶん遅くなります。
- **報告されている性能**:DrivAer(自動車)で、同じ 12 ノードなら A100 搭載ノードが CPU ノードより 3.8 倍速く、結果は統計誤差の範囲で一致しました(AutoCFD5、2026 年 10 月)。
- **導入**:NVIDIA HPC SDK(理究に 26.x あり)でビルドします。Arm CPU(aarch64)でビルドできるかは資料に書かれていません。
- **判断**:断面の極曲線は XLB で十分速くなりました。SPUMA が効くのは、段階 2・3 の 3 次元(MRF・URANS)です。回転格子への対応が出るまでは保留にします。

### C3:ロータをアクチュエータディスクにした軸対称の流れ(天秤の読み、2026-11-01)

羽根を解かずに、ロータを体積力の円盤にして、コップ・モータ・はかりとの干渉と天秤の読みを出せるかを見ました。正解は段階 3 の URANS(回転格子、正転 +0.746 gf・逆転 −0.16 gf)です。実測は +1.675・−0.14 gf です。
- **円盤の力**:半径方向の分布は BEMT(LES の極曲線)から取り、合計を URANS の羽根の力に合わせました(正転 1.4855 gf・155.9 µN·m、逆転 1.85 gf・164.6 µN·m、`cfd/c3/disk.py`、`twin/data/cfd/c3_disk.json`)。ハブは止まった壁としています。
- **OpenFOAM**:5° のくさび形の軸対称格子(約 2.6 万セル)で、円盤は cellZone の体積力です(`cfd/c3/make_axi.py`、ジョブは `cfd/rikyu/13_c3_axi.sbatch`)。乱流は SST か、一定の実効粘性 ν_eff です。集計は `cfd/c3/reduce_axi.py` → `twin/data/cfd/c3_axi.json` です。
- **PINN**:同じ問題を PhysicsNeMo の PDE(旋回つき軸対称 NS)で解きました(`cfd/pinn/c3_axi.py`)。ν_eff = 1.5e-3、6 層 × 256、2 万ステップです。壁の条件は距離関数をかけて厳密に満たし、天秤の読みは壁の圧力と粘性力を積分して出します。データありの場合は、OpenFOAM(ν_eff 1.5e-3)の点を混ぜ、見せていない 4,425 点で誤差を測りました。
- **比較**:`cfd/c3/compare_c3.py`、`twin/data/cfd/c3.png`、`ml_bench.json`(課題 `C3`)です。

- **OpenFOAM の円盤は合格です**。正転・逆転とも、ほとんどの設定で URANS ±0.3 gf に入りました。1 コアで 8〜11 分なので、URANS(2 ノードで 14〜28 時間)の約 1/25,000〜1/50,000 の計算量です(ノード時間で比べて)。部品ごとでは、コップの下向きの力が URANS より小さめ(正転 SST −0.49 gf、URANS −0.65)で、逆転ではかりを押す力が大きめ(SST +1.25、URANS +0.82)です。ν_eff の取り方で ±0.2 gf 動くので、これがこの方法の精度の幅です。
- **データなしの PINN は不合格です**。損失は 0.03 まで下がるのに、流れの向きが逆の解(円盤の上で全域が下向き −1.5〜−2.7 m/s、OpenFOAM は上向き +2 m/s)に落ちました。C1 と同じ「損失は小さいが答えが違う」失敗です。天秤の読みも学習中に 2.2〜2.6 gf の間で揺れ続けました。円盤の縁の力をなめらかにして長く学習すると、読みは +1.1 gf まで下がりましたが、流れ場は同じく逆向きで、読みが近いのは偶然です。
- **データを入れると流れの向きは直ります**。100 点で u_z の誤差 11 %、読み +0.93 gf(URANS +0.19)です。ただし 1,000 点に増やしても良くならず、方程式なしで同じ 1,000 点に合わせた普通の NN(38 秒)のほうが、流れ場の誤差は 1/3、読みも正解に近い結果でした。この問題では、方程式の損失はデータの補間を助けず、むしろ邪魔をしています。
- **天秤の読みの感度**:同じデータに合わせた NN でも、読みは元の OpenFOAM(+0.630)から +0.2〜0.3 gf ずれます。壁の上の圧力の積分が、壁近くの小さな誤差に敏感なためです。
- **結論**:C3 の問い「羽根を解かずに干渉と天秤の読みを出せるか」の答えは、PINN ではなく、OpenFOAM の軸対称アクチュエータディスクです。1 コア 10 分で URANS ±0.3 gf に入ります。PINN は、方程式だけでは間違った解に落ち、データを入れても純粋なデータ補間より劣りました。C4(距離・回転数を入力にする)は、PINN ではなく、この OpenFOAM の円盤をパラメータで回して作るのが速いと考えます(1 ケース 10 分、144 コアで並べれば数十ケースが 10 分)。
- **未解決**:OpenFOAM でも PINN でも、円盤の上で旋回速度 u_θ が、力の向き(+θ)と逆の負になっています。符号の取り方を確かめていません。天秤の読みへの影響は小さいと見ていますが、後流の比較の前に確かめる必要があります。
- **実測との差**:正転の実測 +1.675 gf と URANS +0.746 gf の差は、円盤でも URANS でも説明できていません。段階 3 からの持ち越しの課題です。
